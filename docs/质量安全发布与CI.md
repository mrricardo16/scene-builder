# 质量、安全、发布与 CI

## 质量门

- 每个实现增量必须从仓库根目录执行 `dotnet build SceneBuilder.sln` 和 `dotnet test SceneBuilder.sln`。
- 契约、规则、报告 JSON 示例和未来 JSON 文件必须严格解析；Golden 测试必须比对稳定字段与诊断代码。
- 每次 POC 必须记录输入分类、工具/环境版本、命令、结果、诊断、许可证结论和复现步骤。
- 性能记录必须同时记录正确性抽样；未配置、失败或取消路径的耗时不能作为成功性能结论。

## 安全与资源限制

- 公开仓库禁止真实 CAD 文件、客户名称、设备编码、内部路径、端点、账户、令牌和许可证文件。
- 外部工具只可由受控 Adapter 以参数白名单、显式工作目录和超时启动；禁止由 Web Controller 直接启动。
- 目标 v1 作业命令 `inspect`、`build`、`tiles`、`run` 的运行时写入必须位于调用方提供的作业输出目录及其 v1 作业布局内；其目标报告仅保存相对产物路径。该规则不表示当前已实现这些命令。
- 当前 v0 `doctor` 例外：`--output` 是可选的；指定时仅直接写入调用方目录下的 `doctor-report.json`，省略时不写文件，也不创建 v1 作业目录。该报告可能包含配置的本地工具路径，发布、上传或附加到问题单前必须人工审查并脱敏。
- POC 应设置并记录最大输入字节数、最大实体数、最大作业时间、最大磁盘占用和最大并发数；首版并发为 1。未配置限额时不得宣称已具备生产级资源保护。

## 发布与证据

发布使用语义化版本：契约主版本不兼容时升级主版本；只新增可选字段时升级次版本；文档/修复升级补丁版本。每个发布标签必须关联构建测试日志、支持矩阵状态、已接受 POC 记录和已知限制。

CI 最低检查为：UTF-8 严格解码、禁止敏感文件/关键字的仓库扫描、解决方案构建、测试、JSON 解析、Markdown 内链检查和工作树再生目录检查。CI 不下载或安装候选 CAD/Blender/Tiles 工具；需要许可证或私有样本的 POC 在受控私有环境运行，并只回传脱敏证据摘要。

# 诊断与报告契约

## 当前 Domain `JobReport` v0

当前 `SceneBuilder.Domain.JobReport` 是领域契约，不带 `contractVersion`，也没有 `command`、`parserPath`、`tools` 或 `cache` 字段。其 JSON 属性严格为 `jobId`（字符串）、`createdAt`（日期时间）、`status`（`JobReportStatus`）`diagnostics`（`SceneDiagnostic[]`）和 `artifacts`（`JobArtifact[]`）。

- `JobReportStatus` 枚举成员为 `Pending`、`Succeeded`、`Failed`。
- `SceneDiagnostic` 的 JSON 属性为 `severity`、`code`、`message`、`sourcePath`；`DiagnosticSeverity` 枚举成员为 `Information`、`Warning`、`Error`。
- `JobArtifact` 的 JSON 属性为 `name`、`path`。
- `doctor` 不使用 `JobReport`：它写出独立的 v0 `DoctorReport`，字段为 `generatedAt` 和 `tools[]`；每个工具包含 `name`、`status`、`configuredPath`、`version`、`detail`，状态枚举为 `Available` 或 `Unavailable`。

本节是当前代码事实，不要求也不授权修改 Domain 契约。

## 目标应用报告适配器 v1（尚未实现）

下列 `conversion-report.json` 是未来**应用层报告适配器**的公开契约，不是 `JobReport` 的现有 wire shape，也不能通过直接向 Domain `JobReport` 增字段来实现。开始实现前必须通过迁移门：书面确认消费者、定义 v0 到 v1 适配映射、增加序列化/兼容性测试，并保持现有 Domain 测试通过。只有该门通过后，v1 才可由 [CLI 与作业运行规范](CLI与作业运行规范.md) 的目标命令写出。

v1 根对象必须带 `contractVersion`，首版为 `1.0`。同一主版本只允许新增可选字段；删除、重命名或改变字段语义必须升级主版本。消费者必须忽略未知字段，并拒绝未知主版本且给出可读诊断。

诊断代码使用全大写 ASCII：`域_对象_原因`，例如 `CAD_DOCUMENT_EMPTY`、`DXF_UNIT_UNKNOWN`、`DWG_UNSUPPORTED`、`TILES_NOT_CONFIGURED`。v1 严重级别序列化为 `info`、`warning`、`error`；`error` 表示请求未完整成功，不能仅因报告成功写出就改为成功。

## 目标 v1 字段

| 字段 | 说明 |
| --- | --- |
| `code`、`severity`、`message` | 稳定机器码、级别和面向操作者的中文信息。 |
| `subject` | 可选的匿名对象标识或逻辑位置；不得放入绝对路径、客户名或设备编码。 |
| `parserPath` | 实际使用的解析/回退路径；未调用时明确写 `not-invoked`。 |
| `tools` | 每个候选工具的名称、版本、可用状态；未知版本为 `unknown`。 |
| `cache` | `hit`、`miss`、`bypassed` 或 `not-applicable`。 |
| `artifacts` | 仅列调用方输出根目录下的相对路径、类型和状态。 |

以下 JSON 可以严格解析；这是未配置 DXF 的目标 v1 输出示例，不表示 DXF、DWG 或 Tiles 已实现，也不是当前 v0 `JobReport` 或 `DoctorReport` 的输出。

```json

  "contractVersion": "1.0",
  "jobId": "job-20260728-001",
  "command": "inspect",
  "status": "not-configured",
  "parserPath": "not-invoked",
  "tools": [
    {
      "role": "dxf-parser",
      "candidate": "pending-selection",
      "version": "unknown",
      "availability": "not-configured"
    }
  ],
  "cache": "not-applicable",
  "diagnostics": [
    {
      "code": "DXF_PARSER_NOT_CONFIGURED",
      "severity": "warning",
      "message": "DXF 解析器尚未通过 POC 选型，未执行解析。",
      "subject": null
    }
  ],
  "artifacts": []

```

目标 v1 报告写入失败时，命令应在标准错误输出给出 `REPORT_WRITE_FAILED`，并使用 [CLI 与作业运行规范](CLI与作业运行规范.md) 的退出码 6；不得声称报告已生成。

## SB-10 内部执行诊断

Blender 生成结果不是 `JobReport` v0。内部 `BlenderGenerationResult` 可使用 `BLENDER_MANIFEST_INVALID`、`BLENDER_OBJECT_UNSUPPORTED`、`BLENDER_GEOMETRY_PARAMETER_MISSING`、`BLENDER_EXECUTABLE_NOT_FOUND`、`BLENDER_PROCESS_CANCELLED`、`BLENDER_PROCESS_TIMED_OUT`、`BLENDER_PROCESS_EXITED_NONZERO`、`BLENDER_PROCESS_STATUS_INVALID`、`BLENDER_OUTPUT_MISSING` 和 `BLENDER_OUTPUT_INVALID`。诊断不得回显图纸路径、Manifest 原文、图层、Block 名或完整进程输出。

## SB-11B 内部场景包诊断

`ScenePartitionPlan`、`ScenePackageGenerationResult` 与 `scene-package.json` 也不是 `JobReport` v0 的字段。分区规划使用稳定诊断码：`PARTITION_DRAFT_INVALID`、`PARTITION_OBJECT_BOUNDS_INVALID`、`PARTITION_OBJECT_SKIPPED`、`PARTITION_GRID_INDEX_OVERFLOW`、`PARTITION_OBJECT_ASSIGNED_GLOBAL`、`PARTITION_ANCHOR_OUTSIDE_BOUNDS` 与 `PARTITION_GENERATION_FAILED`。它们只表达对象处理状态，不写入图纸绝对路径、图层、Block、资产路径或 Blender 输出。

场景包发布使用 `SCENE_PACKAGE_PUBLICATION_FAILED`、`SCENE_PACKAGE_PARTIAL`、`SCENE_PACKAGE_INDEX_INVALID` 和 `SCENE_PACKAGE_ARTIFACT_INVALID`。`scene-package.json` 是独立严格契约，当前版本为 `1.0`；只能包含相对 GLB 产物路径和脱敏分区/动态节点信息。任何失败分区都不带 artifactPath，不能因写出 Index 而冒充完整发布成功。

## SB-12A 内部 Tileset 诊断

`tileset.json` 和 `TilesetGenerationResult` 同样不属于 `JobReport` v0。内部诊断包括 `TILESET_INPUT_PACKAGE_INVALID`、`TILESET_POLICY_INVALID`、`TILESET_NO_VALID_PARTITIONS`、`TILESET_CONTENT_GLB_INVALID`、`TILESET_JSON_INVALID`、`TILESET_VALIDATION_FAILED`、`TILESET_ALREADY_EXISTS`、`TILESET_PUBLICATION_FAILED`、`TILESET_GENERATION_CANCELLED` 和 `TILESET_PARTIAL`。它们不得包含包绝对路径、Layer、Block、AssetId、完整 JSON 或 GLB 内容。

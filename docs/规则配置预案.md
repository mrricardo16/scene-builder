# 规则配置预案

规则是项目级数据，不是领域层硬编码。实际 Layer/Block 名称、高度、材质和设备分类只保存在调用方规则文件或私有配置中；公开示例使用合成名称。

## 规则模型

规则至少包含 `id`、`enabled`、`match`、`classification`、`priority` 和可选 `geometryDefaults`。`match` 可包含 Layer 模式、Block 模式和实体类型；模式采用大小写不敏感的通配符，禁止以执行表达式或任意脚本作为规则值。分类固定为 `wall`、`column`、`floor`、`road`、`static-facility`、`dynamic-equipment`、`unclassified`。

实体类型是必需筛选条件：规则声明它时必须精确匹配规范化的大写 DXF 名称（例如 `LINE`、`LWPOLYLINE`、`INSERT`），不依赖具体解析器的 CLR 类型名。仅在所有已声明条件都匹配后，使用以下 `matchRank`（从高到低）比较 Layer/Block；“精确”表示模式不含 `*` 或 `?`：

| `matchRank` | Layer/Block 命中形式 |
| --- | --- |
| 600 | Block 精确且 Layer 精确 |
| 500 | Block 精确且 Layer 通配 |
| 490 | 仅 Block 精确 |
| 400 | Block 通配且 Layer 精确 |
| 390 | 仅 Layer 精确 |
| 300 | Block 通配且 Layer 通配 |
| 290 | 仅 Block 通配 |
| 200 | 仅 Layer 通配 |
| 100 | 仅实体类型 |
| 0 | 默认 `unclassified` |

先选择最高 `matchRank`，再选择数值最大的 `priority`；两者相同才进入并列组。并列组含不同 `classification` 时不任意选择：写入 `RULE_CONFLICT` 错误诊断并保持未分类。并列组分类相同则按 Unicode 序号的 `id` 升序选择第一条，并写入 `RULE_DUPLICATE_MATCH` 信息诊断。该顺序是目标 v1 规则引擎的确定性预案，当前尚未实现。

## 单位与坐标

输入单位先由 CAD 文档声明；未声明或无法映射为米时写入 `DXF_UNIT_UNKNOWN`，不擅自按毫米解释。归一化阶段以米为内部长度单位，并以来源范围的最小 X/Y 形成局部原点。必须拒绝 NaN、无穷值和反向范围，分别报告 `GEOMETRY_INVALID_COORDINATE` 或 `GEOMETRY_INVALID_BOUNDS`。轴向、旋转和 IDTS 坐标映射只在适配层定义，不修改 Domain 契约。

以下为有效 JSON 示例：

```json
{
  "contractVersion": "1.0",
  "rules": [
    {
      "id": "synthetic-wall-layer",
      "enabled": true,
      "priority": 100,
      "match": {
        "layer": "SYN_WALL_*",
        "block": null,
        "entityTypes": ["LINE", "LWPOLYLINE"]
      },
      "classification": "wall",
      "geometryDefaults": {
        "heightMeters": 3.0
      }
    }
  ]
}
```

规则文件版本遵循 [诊断与报告契约](诊断与报告契约.md) 的兼容性原则。引用不存在的规则版本、未知分类或不合法模式必须拒绝执行并报告 `RULE_CONFIG_INVALID`。

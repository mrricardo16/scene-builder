# 规则配置预案

## 已实现的几何前置边界

SB-08 已实现规则 JSON 加载、契约验证和确定性分类。`LINE`、`LWPOLYLINE`、`ARC` 和 `CIRCLE` 可先在 Domain 层形成 `CadContourDocument`：只有源定义闭合的 LWPOLYLINE 和 Circle 才产生候选轮廓，开放曲线保持 `OpenSegments`，不同实体绝不由规则层自动连接。轮廓有效性诊断不得被规则配置吞掉或改写为业务分类；无效轮廓保留为内部 Subject，但固定保持 `unclassified`。

SB-07 的受控修复也不是规则分类：它只在显式米制容差和默认同图层约束下生成/应用审计动作，并把结果重新交给 SB-06 验证。规则层将来若消费修复后结果，必须同时处理原始结果、修复动作和未解决诊断，不能把修复成功等同于墙、房间或设备识别。

规则是项目级数据，不是领域层硬编码。实际 Layer/Block 名称、高度、材质和设备分类只保存在调用方规则文件或私有配置中；公开示例使用合成名称。

## 规则模型

规则至少包含 `id`、`enabled`、`match`、`classification`、`priority` 和可选 `geometryDefaults`。`match` 可包含 Layer 模式、Block 模式和实体类型；模式采用大小写不敏感的通配符，禁止以执行表达式或任意脚本作为规则值。分类固定为 `wall`、`column`、`floor`、`road`、`static-facility`、`dynamic-equipment`；`unclassified` 只用于引擎默认结果，不能作为规则目标。

实体类型是必需筛选条件：规则声明它时必须精确匹配规范化的大写 DXF 名称（例如 `LINE`、`LWPOLYLINE`、`INSERT`），不依赖具体解析器的 CLR 类型名。仅在所有已声明条件都匹配后，使用以下 `matchRank`（从高到低）比较 Layer/Block；“精确”表示模式不含 `*` 或 `?`：

| `matchRank` | Layer/Block 命中形式 |
| --- | --- |
| 600 | Block 精确且 Layer 精确 |
| 500 | Block 精确且 Layer 通配 |
| 490 | 仅 Block 精确 |
| 400 | Block 通配且 Layer 精确 |
| 390 | 仅 Layer 精确 |
| 300 | Block 通配且 Layer 通配 |
| 290 | 仅 Block 通配 |
| 200 | 仅 Layer 通配 |
| 100 | 仅实体类型 |
| 0 | 默认 `unclassified` |

先选择最高 `matchRank`，再选择数值最大的 `priority`；两者相同才进入并列组。并列组含不同 `classification` 时不任意选择：写入 `RULE_CONFLICT` 错误诊断并保持未分类。并列组分类相同则按 Unicode 序号的 `id` 升序选择第一条，并写入 `RULE_DUPLICATE_MATCH` 信息诊断。该顺序已由 SB-08 实现；结果仍是内部契约，不授权 SceneDraft 或三维生成。

## 单位与坐标

输入单位先由 CAD 文档声明；未声明或无法映射为米时，DXF 检查保留 `DXF_UNIT_UNKNOWN`，基础几何标准化返回 `GEOMETRY_UNIT_UNRESOLVED`，不擅自按毫米解释。已实现的基础标准化以米为内部长度单位，并以来源范围的最小 X/Y/Z 形成局部原点；范围非 `Computed` 时返回 `GEOMETRY_BOUNDS_NOT_COMPUTED`，不以 `(0,0,0)` 代替。轮廓修复、轴向重解释、旋转和 IDTS 坐标映射仍只在后续适配层定义，不修改 Domain 契约。

以下为有效 JSON 示例：

```json
{
  "contractVersion": "1.0",
  "rules": [
    {
      "id": "synthetic-wall-layer",
      "enabled": true,
      "priority": 100,
      "match": {
        "layer": "SYN_WALL_*",
        "block": null,
        "entityTypes": ["LINE", "LWPOLYLINE"]
      },
      "classification": "wall",
      "geometryDefaults": {
        "heightMeters": 3.0
      }
    }
  ]
}
```

规则文件版本遵循 [诊断与报告契约](诊断与报告契约.md) 的兼容性原则。引用不存在的规则版本、未知分类或不合法模式必须拒绝执行并报告 `RULE_CONFIG_INVALID`。

## SceneDraft 消费边界

SB-09 只接收已经得到的 `CadClassificationResult`，不会重新匹配规则。有效的 Wall、Floor、Column、Road、StaticFacility 和 DynamicEquipment 会先核验实际 Subject 与来源几何，再进入内部 SceneDraft；`unclassified` 不生成对象或节点。`HeightMeters` 仅原样供 Wall 与 Column 使用，缺失或不可用时保留对象但不补经验高度，并给出内部非阻塞诊断。Floor 不将其解释为厚度，Road 不将其解释为宽度，设施不将其解释为缩放或资产路径。

# 路线图与任务卡映射

本映射以 [产品目标与能力状态](产品目标与能力状态.md) 和 [Avalonia Desktop 路线图](scene-builder-avalonia-desktop-roadmap.md) 为唯一产品路线来源。历史 SB-00 至 SB-12A 说明底层能力演进；它们不是当前 Desktop 产品路线，也不得与下列任务卡并列造成冲突。

| 阶段 | 任务卡 | 产物 | 明确非目标 |
| --- | --- | --- | --- |
| 共享宿主与 CLI 框架 | CORE-01 | 公共执行契约、能力表、组合根、doctor/capabilities CLI | 真实 Build、完整 convert 或 Desktop 直连 CAD/Blender/Tiles。 |
| CAD 分析 | CORE-02 | `CadImportAnalysisResult`、受限 DXF Analyze CLI | 启动 Blender。 |
| 计划 | CORE-03 | 可编辑 Draft、校验结果、Frozen Plan | 修改原始 CAD 或让 Build 读 ViewModel。 |
| 分析快照 | CORE-04A | Analysis v2、Build Input Snapshot v1 | 升级 Frozen Plan v1 或生成三维产物。 |
| 构建准备 | CORE-04B | Snapshot 绑定、完整配置冻结、Frozen Plan v2 | 在 04A 中创建 SceneDraft 或启动生成器。 |
| 构建 | CORE-04C | GLB、Scene Package、3D Tiles 输出协调 | 重新猜测 UI 参数。 |
| DXF 闸门 | CAD-DXF-01 | 真实 DXF 支持证据 | 以 SmokeTest 冒充通用支持。 |
| DWG 闸门 | CAD-DWG-01 | DWG Adapter 与支持证据 | 在闸门前声称 DWG 已支持。 |
| 桌面验证 | DESKTOP-00 | 2D CAD、GLB、3D Tiles Viewer POC 结论 | 直接交付未验证预览。 |
| 桌面产品 | DESKTOP-01 至 DESKTOP-09 | 宿主、导入、调整、输出、历史、预览、发布 | 改写 Domain 或绕过 Application。 |
| 大厂区 Tiles | LARGE-00 至 LARGE-04 | 样本基线、HLOD、GLB 优化、缓存与 Viewer 验收 | 将 SB-12A 单层索引冒充大型厂区生产方案。 |
| 集成 | INTEGRATION-01 | 可选 IDTS API/Web 适配评估 | 在核心工作流稳定前提前接入。 |

每张任务卡都必须写明目标、前置条件、输入、稳定契约、实现范围、非目标、验证、退出条件与能力状态变化条件。任务卡未完成时，能力状态不得上调。

## 已实现基线的正确引用

当前代码已提供受限 DXF 分析、Analysis v2/Build Input Snapshot v1、SceneDraft、受控 Blender GLB、显式资产映射、Scene Package 和本地 Cartesian 3D Tiles 1.1。CORE-01 建立统一宿主；CORE-02、CORE-03、CORE-04A 和 CORE-04B 已注册真实 Analyze、Plan、Snapshot 与 Build-ready Frozen Plan 数据链路；CORE-04C 仍未实现。现有底层生成器、测试和 SmokeTest 不是完整 `convert` CLI、Avalonia 页面或用户产品入口。

## 大厂区 3D Tiles 路线

大厂区路线遵循 `CORE-04B → CORE-04C + LARGE-00 → LARGE-01 → LARGE-02 → LARGE-03 → LARGE-04`。其中 LARGE-00 建立真实样本与基准，LARGE-01 定义并验证多层 Tileset/HLOD，LARGE-02 处理 GLB 资产和实例优化，LARGE-03 才评估增量构建与缓存，LARGE-04 验收受控 Viewer。CAD-DXF-01 与 CAD-DWG-01 持续决定输入支持边界。
# CORE-02 完成状态

CORE-02 已实现 Analyze 基础：中立输入适配器、受控 DXF、副本分析结果与 CLI。CORE-03 才引入可编辑 Conversion Plan；CORE-04 才引入冻结和多格式 Build。

# CORE-03 完成状态

CORE-03 已实现 Draft revision、validation 与 Frozen Plan 的受控 Artifact 生命周期。CORE-04B 负责把 Analysis/Snapshot 和完整语义配置冻结为 Build-Ready Frozen Plan；CORE-04C 才负责把它消费为三维产物。

# CORE-04 状态拆分

- CORE-04 Gate：Completed；Frozen Plan v1 仍返回 `FROZEN_PLAN_NOT_BUILD_READY`。
- CORE-04A：Completed；Analysis v2 与 Build Input Snapshot v1 可用。
- CORE-04B：Completed；负责 Snapshot 绑定、语义配置冻结、资源内容寻址和 Build Readiness Frozen Plan v2。该状态不等于 Build Available。
- CORE-04C：Planned；负责 SceneDraft、GLB、Scene Package 与 3D Tiles 构建。

CORE-04B 的验证边界是 Analysis v2 + Snapshot v1 + Frozen Plan v2 的确定性数据链路。v1 Frozen Plan 不自动升级；CORE-04C 仍必须只消费 Readiness 为 Ready 的冻结计划。

# 路线图与任务卡映射

> SB-06 实施补充：在语义分区规则之前，先完成“二维轮廓构建与几何验证”。其输入为 SB-05 的标准化米制几何，产物为 `CadContourDocument`，不会生成 SceneDraft 节点或分区。详细门禁见 [SB-06：二维轮廓构建与几何验证](task-cards/SB-06-轮廓构建与几何验证.md)；后续分区工作必须消费经验证的轮廓或显式处理其诊断，不能绕过该边界。

> SB-07 实施补充：在任何规则或分区之前，可对 SB-06 的开放段执行显式策略驱动的受控修复。其产物是内部 `CadGeometryRepairResult`，并重新复用 SB-06 验证；它不改变 JobReport、SceneDraft 或对外 CAD/DWG 支持状态。详细门禁见 [SB-07：几何容差、散线连接与受控修复](task-cards/SB-07-几何容差与受控修复.md)。

> SB-08 实施补充：本实施编号覆盖下表早期“对外支持矩阵”预案编号。SB-08 在 SB-05 至 SB-07 的可信二维结果上完成项目级 Layer、Block 与 EntityType 的确定性分类，产物为内部 `CadClassificationResult`，不生成 SceneDraft 或三维模型。详细门禁见 [SB-08：图层、Block 与实体类型规则引擎](task-cards/SB-08-图层Block与实体类型规则引擎.md)。

> SB-09 实施补充：本实施编号覆盖下表早期“性能基线”预案编号。SB-09 已把可信分类结果、最终轮廓文档和标准化 Insert 映射为内部 `CadSemanticObject`、`SceneNode` 和 `SceneDraft`；它没有生成任何 Mesh、GLB 或 Tiles。详细门禁见 [SB-09：厂房语义对象与 SceneDraft](task-cards/SB-09-厂房语义对象与SceneDraft.md)。

> SB-10 实施补充：SceneDraft 现在可经版本化内部 Manifest 和受控 Blender 后台进程生成最小单场景 GLB。实现范围、进程安全边界、GLB 校验和明确非目标见 [SB-10：Blender 进程与最小三维草模](task-cards/SB-10-Blender进程与最小三维草模.md)。

> SB-11A 实施补充：静态设施和动态设备以显式 Catalog/Binding 映射到 GLB；Windows 资产读取使用句柄级的重解析点防护。该任务不引入分区、Tiles 或 IDTS 接入，详见 [SB-11A：GLB 资产映射与句柄安全](task-cards/SB-11A-GLB资产映射与句柄安全.md)。

> SB-11B 实施补充：既有 SceneDraft 可按固定米制 XY 网格规划为稳定分区，经受控 staging 生成和发布多个独立 GLB 与 `scene-package.json`。它不重新解析、分类或修改 SceneDraft/JobReport v0，详见 [SB-11B：空间分区与多 GLB 场景包](task-cards/SB-11B-空间分区与多GLB场景包.md)。

## 共同进入与退出条件

- 进入：输入样本来源合规、公开/私有分类完成，所用契约已在本目录说明，命令和退出码已在 [CLI 与作业运行规范](CLI与作业运行规范.md) 固定。
- 退出：报告包含诊断、工具版本、缓存状态和产物清单；测试结论与 POC 决策记录可追溯；能力状态同步到 [CAD 支持矩阵](CAD支持矩阵.md)。
- 任何候选工具失败、超时、无许可证结论或无法复现时，卡片只可产出失败/未配置证据，不能修改对外支持状态。

## Avalonia Desktop（设计/规划）

> Windows 10/11 Avalonia Desktop 是设计中的 DXF-only 本地 MVP，并非当前已实现产品。SB-11A 已在 `main` 当前提交中；SB-11B 仍是工作区未提交工作，不计为完成，也不混入桌面范围。桌面接入须等待 SB-10.5 的统一 Application/CLI 入口；DWG 显示“暂不支持”，3D Tiles/Cesium 仅在 SB-11B、SB-12 已验证后的 DESKTOP-09 独立评估。

桌面路线、依赖与 DESKTOP-00 至 DESKTOP-09 卡片见 [Avalonia Desktop 路线图](scene-builder-avalonia-desktop-roadmap.md)。该规划不改变 `SceneBuilder.Domain`、CAD、Blender、资产映射或 `JobReport v0`。
